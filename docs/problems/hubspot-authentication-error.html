HubSpot Signature Validation Error 401 Unauthorized

Type URI
https://api.marketingpod.dev/problems/hubspot-signature-validation-error
Status Code
401 Unauthorized
Description
Requests from HubSpot must include valid x-hubspot-signature-v3 and x-hubspot-request-timestamp headers. This error occurs when one or more of the following is true: the headers are missing, the timestamp is older than 5 minutes, or the computed signature does not match the value in x-hubspot-signature-v3.
Expected Headers
  • x-hubspot-signature-v3: <base64 HMAC-SHA256>
  • x-hubspot-request-timestamp: <unix ms timestamp>

Example Response

{
  "type": "https://api.marketingpod.dev/problems/hubspot-signature-validation-error",
  "title": "Error authenticating HubSpot signature",
  "status": 401,
  "detail": "Missing or invalid x-hubspot-signature-v3; check timestamp and signature construction.",
  "instance": "/api/v1/integration/req_1704123456789_abc",
  "requestId": "req_1704123456789_abc",
  "timestamp": "2024-10-07T12:34:56.789Z"
}

Validation Rules

  • Reject if now - x-hubspot-request-timestamp > 5 minutes.
  • Build the source string: requestMethod + requestUri + requestBody + timestamp.
  • Create HMAC-SHA256 with your HubSpot app secret, then Base64-encode the result.
  • Compare your computed value to x-hubspot-signature-v3 using a constant-time comparison.

Common Causes

  • Missing x-hubspot-signature-v3 or x-hubspot-request-timestamp header.
  • Timestamp older than 5 minutes (clock skew or replayed request).
  • Concatenation uses the wrong requestUri (must include scheme, host, and path you received).
  • Body mismatch due to re-encoding/minified JSON (use the exact raw request body string).
  • Including a body for GET requests (should be empty when constructing the source string).
  • Using the wrong secret (use the app’s client secret for the HubSpot app that sent the request).

How to Fix

  1. Ensure both headers are present and your server clock is accurate (NTP synced).
  2. Read the raw request body as a string without reformatting or sorting keys.
  3. Construct the string: {METHOD}{URI}{RAW_BODY}{X-HubSpot-Request-Timestamp}. For example: 
    POSThttps://example.com/webhooks{"eventId":123}1730909999123
  4. Compute Base64(HMAC_SHA256(sourceString, HUBSPOT_APP_SECRET)).
  5. Compare (constant-time) with the value in x-hubspot-signature-v3.
  6. If the timestamp is too old or the signature doesn’t match, respond with this 401 and do not process the payload.

Example: Pseudocode

// Pseudocode
const ts = headers["x-hubspot-request-timestamp"];
const sig = headers["x-hubspot-signature-v3"];
if (!ts || !sig) return 401;

if (Date.now() - Number(ts) > 5 * 60 * 1000) return 401;

const uri = request.fullUrl;                // scheme + host + path (and query if present)
const body = request.rawBodyString || "";   // exact raw bytes as string
const source = request.method + uri + body + ts;

const expected = Base64(HMAC_SHA256(source, HUBSPOT_APP_SECRET));

if (!timingSafeEqual(expected, sig)) return 401;
